# Scene Splitter Skill: A Literary Editor's Assistant

## 📖 Overview
This skill acts as a sophisticated structural editor for novel manuscripts. Its primary function is to take a single, large file (expected to be a novel chapter) and intelligently break it down into smaller, self-contained "scenes." A scene is defined as a distinct unit of action, character focus, or setting, allowing the user to improve pacing, structural review, or submission organization.

## 📥 Input Requirements
1.  **Input File:** The skill requires one input file, which must contain the full text of a chapter from a novel.
2.  **Chapter Metadata:** Chapter title or primary header information is expected to be at the very beginning of the file, but this metadata **must not** be included in the generated scene files.

## 🧠 Scene Detection Logic (Instructions for the LLM)
When analyzing the input file, use the following logic to determine scene boundaries:

1.  **Primary Heuristics (Best Judgement):** A scene break should be triggered by one or more of the following:
    *   **Significant Change of Location:** The narrative physically moves to a different setting (e.g., from a library to a park).
    *   **Major Time Jump:** A noticeable passage of time occurs (e.g., "The next day," "Three weeks later").
    *   **Shift in Character Focus:** The perspective radically changes, or the narrative focus shifts heavily to an entirely new character who was previously backgrounded.
2.  **Output Goal:** Each segment must be self-contained and represent a complete, emotionally or narratively satisfying unit. Do not split scenes simply because of excessive dialogue; split them only when the *context* changes.

## 💾 Output Workflow (Execution Steps)
The skill must perform the following actions in sequence:

**Step 1: Metadata Extraction & Isolation**
*   Identify and extract any chapter title, running header, or metadata from the very beginning of the original file.
*   Isolate this metadata, but **do not include it in any scene file**.

**Step 2: Scene Segmentation**
*   Using the logic described above, segment the body content of the chapter into $N$ scenes.

**Step 3: File Generation**
*   **Target Directory:** Create a subdirectory named `scenes/` within the same directory as the original input file.
*   **File Naming Convention:** For each scene, save it as a markdown file (`.md`) following this pattern: `[OriginalFileName]-scene-[SceneNumber].md`.
*   **Content Saving:** Each generated scene file must only contain the scene's narrative text and markdown formatting. It must not contain any chapter metadata or headers.

**Step 4: Validation (Crucial Step)**
*   After all scenes are saved, use the provided script, `scripts/validate_scenes.py`, to perform a comprehensive content integrity check.
*   **Validation Goal:** This script must confirm that if all the content of the generated scene files are concatenated, the resulting text is virtually identical to the original input file, excluding only the chapter's metadata/title line.
*   **Final Output:** The skill must conclude by presenting a clean summary that includes:
    1.  A confirmation of the total number of scenes created.
    2.  A markdown block containing the result and summary generated by `validate_scenes.py`.

## ⚙️ Helper Script: `validate_scenes.py`
The script `scripts/validate_scenes.py` is required for the final validation step. This script will take the original file path and the newly created scene files as inputs. It must programmatically:
1.  Concatenate the content of all scene files.
2.  Compare the concatenated content against the original file content (minus the title/metadata line).
3.  Output a clear boolean result and summary statement indicating success or failure.

**Example Usage:**
*   Original File: `chapters/ch01.md`
*   Scripts Path: `scripts/validate_scenes.py`
*   Scene Files: `scenes/ch01-scene-01.md`, `scenes/ch01-scene-02.md`, etc.
*   *The skill must call this script to validate.*

## 📜 Self-Correction and Guidelines
*   **Immutability:** The original input file MUST NEVER be altered or overwritten.
*   **Clarity:** Always explain your segmentation decisions to the user if the split is non-obvious.
*   **Robustness:** If the input file cannot be identified as a novel chapter (e.g., it's a PDF transcript, a legal document, or pure code), the skill must respond gracefully, stating that the content does not appear to be a novel chapter and refusing to split it.
\n\n*Always remember to run the `validate_scenes.py` script in the final step to prove structural integrity.*"
